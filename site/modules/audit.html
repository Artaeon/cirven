cirven audit

Reads your system, changes nothing, and tells you how an attacker would get in. Findings are ranked by the attack paths they open, not by checklist order.

usage

$ cirven audit
[high] ~/.bash_history:412  github token in plaintext (ghp_****)
[high] sshd: PasswordAuthentication yes, port 22 open on 0.0.0.0
       path: exposed sshd + password auth -> remote brute force
[med ] no firewall rules loaded (nftables empty)
[ok  ] root fs on LUKS2, argon2id
[ok  ] secure boot enabled, own keys enrolled
5 findings, 2 high. run cirven harden --plan to fix.

checks

  • network: listening sockets, firewall state, exposed services
  • ssh: sshd config, authorized_keys, unencrypted private keys, agent forwarding
  • secrets: tokens and keys in shell history, dotfiles, .env files, git configs
  • disk: LUKS version and KDF, swap and hibernation encryption
  • boot: secure boot, bootloader and kernel cmdline, unsigned modules
  • accounts: sudo rules, passwordless sudo, polkit, PAM stack
  • updates: pending security updates, kernel age, stale packages
  • desktop: screen lock timeout, autostart entries, world-readable home files

output

Human-readable by default. --json for machines, --sarif for CI. Exit code reflects the highest severity, so it can gate scripts.

threat model

Stops: misconfigurations an attacker would use, found before they are. Does not stop: an attacker already on the machine; they can lie to any tool running beside them. For that, see watch.
