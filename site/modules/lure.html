cirven lure

Infostealers grab whatever looks valuable. lure gives them something that looks valuable and is worth nothing except the alarm it raises. You never touch the decoys, so any access is a signal with almost no false positives.

usage

$ cirven lure plant
~/.aws/credentials.bak          fake aws key pair
~/.ssh/id_ed25519_old           fake private key
~/projects/.env.production      fake db url + api tokens
~/.config/chromium-backup/      fake login store
$ cirven lure status
[tripped] ~/.ssh/id_ed25519_old read by pid 4410 /tmp/.u/upd

two tripwires

  • read: fanotify reports which process opened a decoy. local, offline, instant.
  • use: decoy tokens and URLs call home when an attacker tries them elsewhere, so you learn about the leak even if the read was missed. needs a callback endpoint: self-hosted, or cirven relay.

threat model

Stops: unnoticed credential theft by malware, poisoned packages, and curious agents. Does not stop: an attacker who reads only real secrets. Decoys sit next to them on purpose, and real secrets belong in a vault (see key).
