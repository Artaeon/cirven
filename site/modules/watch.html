cirven watch

Malware that wants to survive a reboot has to write somewhere. watch knows those places, keeps a baseline, and tells you when one changes, and why that matters.

usage

$ cirven watch baseline
indexed 214 persistence points.
$ cirven watch
[alert] new user unit ~/.config/systemd/user/dbus-helper.service
        ExecStart=/home/r/.cache/.x/run  (binary in cache dir, hidden name)
        written by: pid 8812 /usr/bin/python3 setup.py

watched

  • systemd units and timers, system and user
  • xdg autostart, compositor exec lines (hyprland exec-once, sway exec)
  • shell rc files: .bashrc, .zshrc, .profile, fish conf.d
  • cron, at, anacron
  • ~/.ssh/authorized_keys, ssh config ProxyCommand
  • /etc/ld.so.preload, LD_PRELOAD in environment files
  • pacman hooks, udev rules, PAM config, sudoers.d, kernel modules
  • git hooks and core.hooksPath, editor plugin dirs

how

fanotify for live events with the writing process attached, plus a hashed baseline to catch changes made while watch was not running. Alerts go to the desktop, a log, or a webhook.

threat model

Stops: silent persistence by user-level malware, poisoned packages and install scripts. Does not stop: a root-level attacker who disables watch first. Tamper attempts are logged, and the baseline can be checked from a clean boot.
